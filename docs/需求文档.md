## 1. 背景与问题

### 1.1 文本本身的门槛

《三国演义》对现代读者的阅读障碍不在文言，而在**三个不同步**：

1. **称谓不同步**：同一个人在一回里可能叫「关羽」「云长」「关公」「关将军」「汉寿亭侯」「美髯公」。读者看到一个陌生称谓，要回溯几十行才知道是谁。
2. **地理不同步**：书里的地名是东汉地名（雒阳、江陵、夏口、白马），与今地名不对应；「荆州」「益州」既是州域又是一座城，读者无从判断是行军三百里还是三十里。
3. **时间不同步**：叙述顺序不等于时间顺序，插叙、并叙频繁；读者知道「这年曹操在官渡」，但不知道此刻某个此前活跃的人物是否还活着、属于哪一方。

### 1.2 现有解法为什么不够

| 现有解法 | 缺什么 |
|---|---|
| 全文检索 | 只能匹配字面。「云长」搜出来一堆，不知道是同一个人 |
| 百科/Wiki | 条目与原文割裂，读完条目还要回去找原文哪一段 |
| 纸质或静态地图 | 与正文零联动，查一次要翻两处 |
| 影视/讲书 | 失去原文细节与可引用性 |
| 大模型问答 | 答案不可追溯，会编 |

**核心判断**：读者要的不是「读得更快」，而是「读到任何一处，能用一次点击知道自己缺的那点背景，然后继续读」。这个动作必须**在原文之内完成**，且**答案必须能回链到原文**。

### 1.3 本产品的回答

把原文的每一处人名、地名做成**锚点**，锚点链到**有出处的实体卡**；把时间与地理做成**可推演的两张图**，与锚点互通。全部离线，纯静态文件，双击即开。

## 2. 产品定位

**一句话**：《三国演义》的可追溯结构化读本——每个名字有卡，每个地名有位，每段时间有图。

**是什么**：面向个人深度阅读的离线读物 + 数据/渲染管线。

**不是什么**（划界比列举功能更重要）：

- 不是阅读器 App：不提供书城、书签同步、多书管理。
- 不是百科：不做独立条目检索入口，一切从原文出发。
- 不是 AI 问答：不生成未经人工确认的内容上屏。
- 不是学术影印：不做版本校勘，底本是通行本。
- 不是通用地图：只服务本书出现的地点与路线。

## 3. 目标用户与典型场景

| 编号 | 用户 | 场景（触发 → 动作 → 期望） |
|---|---|---|
| U1 | 初读者（学生为主） | 读到「操曰：『吾知绍之为人，志大而智小』」→ 点「绍」→ 期望一眼看到袁绍是谁、此刻在什么位置、势力多大，不打断阅读节奏 |
| U2 | 重读者/爱好者 | 想比较官渡前后的战线变化 → 打开官渡战役卡 → 期望按时间节点推进，看到每一步的地点与兵力对比 |
| U3 | 内容创作者/教师 | 需要引用「衣带诏」原文 → 期望从事件卡直接跳到原文那一段，并能复制出处（回目 + 段号） |
| U4 | 数据维护者（本项目特有） | 铺完新一批回目 → 期望一条命令知道数据有没有坏、页面有没有白屏，而不是手敲截图命令 |

> U4 是真实用户：本项目的内容维护成本远高于代码维护成本，因此「批产质量可验证」本身就是产品需求（见 R-8）。

## 4. 产品目标与非目标

### 4.1 目标

| 编号 | 目标 | 可度量口径 |
|---|---|---|
| G1 | 可追溯 | 每个锚点可解析到实体；每张实体卡的关键判断（身份、时间片）有 basis 依据文本 |
| G2 | 身份正确 | 人物阵营随时间变化（关羽 200–208 属群雄·武将，非蜀汉），不出现"一人一阵营"的错标 |
| G3 | 地理正确 | 地名有像素坐标与坐标精度档；相邻州界无缝隙无重叠 |
| G4 | 时间正确 | 生卒年不编造；无把握时如实标「约/不详/存疑」 |
| G5 | 可验证 | 任意一次改动后，一条命令给出通过/失败与失败点 |
| G6 | 可增量 | 新增 10 回内容不需要改代码，只加数据文件并补一条索引 |

### 4.2 非目标

| 编号 | 非目标 | 理由 |
|---|---|---|
| N1 | 社交、评论、账号 | 个人离线读物，无服务端 |
| N2 | 逐句白话翻译 | 与"回到原文"的定位冲突，且是另一个产品 |
| N3 | 自动生成内容直接上屏 | 批产内容必须过校验或人工过目，见 D-9 |
| N4 | 支持演义之外的文本（三国志、后汉书） | 数据模型可扩展，但当前不做 |
| N5 | 原生移动 App | P2 阶段评估 Tauri 壳，当前是浏览器页面 |
| N6 | 服务端检索/推荐 | 无服务端 |

## 7. 数据口径需求（产品级，不是实现细节）

这一节是本项目区别于「随便标一标」的地方。每条口径都直接决定用户看到的结论对不对。

| 编号 | 口径 | 要求 | 为什么是产品需求 |
|---|---|---|---|
| D-1 | 身份是时间片，不是字段 | 每人可有多段归属，带起止年、官职、依据（basis） | 若按「一人一阵营」建模，关羽会被标成蜀汉——而蜀汉 221 年才建立，关羽 220 年已死。用户看到的就是错的 |
| D-2 | 生卒年三档精度 | `approx`/`unknown`/`disputed` 三档必须显式标注，并附依据；禁止编造精确年 | 编一个看似精确的年份，会让读者误以为有据可查。这是硬约束，schema 全局校验规则第 5 条 |
| D-3 | 演义优先，史异注 | 正文从演义；史实差异写在卡片注释里，不改正文 | 读者点「关羽斩华雄」却看到「非关羽所为」，阅读体验割裂（详见待确认问题清单 P1-1） |
| D-4 | 无名女性可收但要折叠 | 完全无名但承担不可替代情节功能者（如刘安之妻）收，标 `is_nameless`，折叠显示 | 收进来会稀释可信度，不收会丢情节节点。折叠是折中 |
| D-5 | 神怪独立阵营 | 有超自然能力表现且不属于任何军政集团者归「神怪」；张角仍归群雄·君主 | 「张角是神怪还是军阀」若不定，身份体系会自相矛盾 |
| D-6 | 坐标三档精度 | 精确／近似／存疑；演义虚构地名（东岭关、古城）标「示意」 | 让读者知道这个点能不能当史实用。虚构地名不标，等于把小说当史书 |
| D-7 | 弱链接 | `is_weak_link` 锚点不弹全卡，只就地提示一句 | 弹卡等于用确定的卡掩盖不确定的推理。**已实现**（R-1.6）。注：现 74 条弱链接均来自单字回指，官职代称通道尚未实现 |
| D-8 | 战役必挂父事件 | 允许父事件是「军事行动」类轻量事件 | 否则战线图没有归属，读者看不到「这一仗是为了什么」 |
| D-9 | 批产内容分级审核 | `draft`/`auto_generated`/`reviewed`/`verified` 四档；`verified` 必须有 basis | 让"哪些内容可信"对用户与维护者都可见 |

## 附录 A 术语表

| 术语 | 含义 |
|---|---|
| 锚点（mention） | 原文中一段被识别为实体的连续文字，含段内起止偏移 |
| 时间片（tenure） | 人物在某阵营、某身份、某官职下的有效期 |
| 弱链接 | `is_weak_link = true` 的锚点：证据不足以确定指向（如同段「嵩」可指曹嵩或皇甫嵩），只提示不弹卡 |
| 感知缩放（pz） | 视图比例 × 实际显示宽 / 画布宽，即"屏幕上看起来放大多少倍" |
| 注记分级 | 按感知缩放逐级显隐地名注记的规则 |
| 快照年 | 大势数据中手工考据的年份节点，其间取最近快照 |
| 战线节点 | 战役推进的时间步，含坐标、标题、说明 |
| 深链 | 可直接定位到具体状态的 URL 片段 |
